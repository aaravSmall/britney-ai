DATA & BACKEND
- Real performance history: dashboard's 30-day chart is still a random mock
  seeded from user id, unrelated to actual trades/holdings. Need a daily
  snapshot table (portfolio value per user per day) to make it real.
- Websocket/streaming quotes instead of polling Yahoo/CoinGecko on each
  dashboard load — cheaper and feels more "live".
- Move off the Yahoo Finance unofficial endpoint before any real launch —
  see docs/TECH_STACK.md for paid alternatives (Alpaca/Polygon/IEX).
- Trade history / order log screen (right now a fill just mutates
  cash + holdings, nothing records that the trade happened).
- Real cash ledger instead of a single cash_balance float (deposits,
  withdrawals, dividends, fees down the line).

TRADING
- REMINDER before the agent (prompt 4) starts trading on a schedule:
  get_or_create_portfolio() is currently only called from build_dashboard's
  path (via ensure_demo_holdings) and from record_trade_fill itself, but
  ensure_demo_holdings is NOT called from record_trade_fill — so a
  portfolio that's never been loaded via /dashboard (pre-existing
  CORS/first-load timing edge case) can still be traded against, just
  without demo seed holdings. Before the agent trades on a schedule
  without a user ever having opened /dashboard first, make
  record_trade_fill call get_or_create_portfolio() directly (it already
  does) AND decide whether it should also seed/initialize like
  ensure_demo_holdings does, so a never-loaded portfolio can't cause a
  failed/mysterious agent trade. Flagged 2026-08-04, not yet implemented.
- Actual Alpaca live/paper order routing (execution.py has a placeholder
  for this — currently everything is simulated locally).
- Fractional share support / rounding rules for crypto vs stock vs option
  quantities.
- Recurring/auto-invest execution (auto_invest_enabled toggle exists but
  nothing runs on a schedule yet).

AGENT — CRYPTO NEWS (plan only, not implemented; flagged 2026-08-04)
- Gap: backend/agent/news_ingestion.py only fetches stock/ETF news via
  Finnhub's free /company-news endpoint, which doesn't cover crypto —
  BTC/ETH/SOL are listed in TARGET_PORTFOLIOS but silently skipped. The
  agent isn't feature-complete until it has a crypto news source too.
- Source options (free-tier-first, roughly in order of how much cleanup
  they'd need before feeding the sentiment/decision loop):
  - CryptoPanic free tier — purpose-built crypto news aggregator, already
    tags posts with currency codes (closest analog to Finnhub's `related`
    field), but the free API has gotten stingier over time (auth token
    required, low request quota) — needs checking at implementation time.
  - CoinDesk / CoinTelegraph (or similar) RSS feeds — free, no key, no
    rate limit beyond "don't hammer it," but no ticker tagging at all:
    would need keyword/symbol matching against headline+body to attribute
    an article to BTC/ETH/SOL, and no stable article id (would hash the
    URL, same trick as any id-less source).
  - Reddit (e.g. r/CryptoCurrency, r/Bitcoin) via the public `.json`
    endpoints — free, no auth for read-only, but noisier signal per-post
    than news articles; probably wants aggregation across many posts
    rather than per-post scoring, and needs a custom User-Agent header or
    Reddit rate-limits/blocks the requests.
  - CryptoCompare News API — another free-tier aggregator option, similar
    tradeoffs to CryptoPanic, worth a quick comparison before picking one.
- Interface: whichever source(s) get picked should normalize into the
  exact same NewsArticle shape news_ingestion.py already produces
  ({ticker, headline, summary, source, url, published_at, article_id}),
  either via a new fetch_crypto_news() alongside fetch_news() or by
  extending fetch_news() to branch on asset_type internally. Either way
  the goal is that agent/sentiment.py and the future decision-loop module
  don't need to know or care which provider a given article came from.
- Gotchas:
  - Crypto trades 24/7 — no market-hours gating like stocks implicitly
    get. Whatever polling/scheduling cadence the agent ends up using for
    stock news shouldn't just be reused verbatim for crypto; crypto news
    can matter just as much at 3am as 3pm.
  - Ticker attribution from free-text sources (RSS/Reddit) is fuzzy —
    keyword matching risks both false positives (e.g. "ETH Zurich") and
    false negatives (nicknames, tickers not mentioned verbatim).
  - Rate limits and ToS vary a lot across these free options and are
    worth re-checking right before implementation, not just at planning
    time — free tiers change terms/quotas without much notice.
