britney.ai — future ideas / plans
(running notes, not commitments — add/cross off freely)

DATA & BACKEND
- Websocket/streaming quotes instead of polling Yahoo/CoinGecko on each
  dashboard load — cheaper and feels more "live".
- Move off the Yahoo Finance unofficial endpoint before any real launch —
  see docs/TECH_STACK.md for paid alternatives (Alpaca/Polygon/IEX).
- Real cash ledger instead of a single cash_balance float (deposits,
  withdrawals, dividends, fees down the line). Note: audit showed float
  drift is negligible (~8.5e-9 at 100k simulated trades) — refactor is for
  auditability, not precision.

TRADING
- REMINDER before the agent starts trading unattended without a user ever
  having opened /dashboard first: get_or_create_portfolio() is currently
  only called from build_dashboard's path (via ensure_demo_holdings) and
  from record_trade_fill itself, but ensure_demo_holdings is NOT called
  from record_trade_fill — so a portfolio that's never been loaded via
  /dashboard (pre-existing CORS/first-load timing edge case) can still be
  traded against, just without demo seed holdings. Need to make
  record_trade_fill decide whether it should also seed/initialize like
  ensure_demo_holdings does, so a never-loaded portfolio can't cause a
  failed/mysterious agent trade. Flagged 2026-08-04, not yet implemented.
- Actual Alpaca live/paper order routing (execution.py has a placeholder
  for this — currently everything is simulated locally).
- Fractional share support / rounding rules for crypto vs stock vs option
  quantities. Note: frontend display of fractional crypto quantities was
  fixed in the Sprint 2 frontend audit (8-decimal trim) — this item is
  about backend rounding rules across asset classes, still open.
- Recurring/auto-invest execution (auto_invest_enabled toggle exists but
  nothing runs on a schedule yet).

FRONTEND / UX
- Holdings detail screen (tap a position -> price history, buy/sell,
  cost basis, P/L). CC prompt already drafted, not yet run.
- Notifications (price alerts, trade confirmations, daily digest).
- Stock search: search any ticker (not just recommended assets), land on a
  detail page with price/chart + company info (name, sector, description,
  market cap, etc.), and buy/sell straight from there. Needs a backend
  endpoint for company fundamentals/profile — current market_data.py only
  fetches a bare price, not company metadata. CC prompt already drafted,
  not yet run.
- Onboarding: capture more nuanced risk profile inputs (current fields are
  pretty coarse: risk_tolerance/goals/time_horizon strings).
- Mobile builds (android/ios folders aren't generated yet — currently
  flutter web only in practice).

AI
- Stream chat responses instead of waiting for the full completion.
- Let recommendations reference the user's *actual* current holdings
  (right now it's generated independent of the portfolio).
- Guardrails/eval pass on recommendation output before showing it.
- Discovery gate (b)'s company-name alias table: two real rejections
  (2026-08-17/08-20) are the SAME real company/ticker as the LLM claimed
  but score zero-to-borderline token overlap for reasons no
  suffix-stripping fixes — RTX (LLM said "Raytheon Technologies
  Corporation", Yahoo's quote is now "RTX Corporation" post-2023 rename)
  and 2222.SR (LLM said "Saudi Aramco", Yahoo's formal legal name is
  "Saudi Arabian Oil Company"). Deliberately not solved by the
  2026-08-22 suffix-list fix (see
  memory/project_discovery_gateb_false_rejects.md) — needs a real
  alias/rename table, a separate, larger feature, not a normalization
  tweak.

INFRA
- PROMOTION CANDIDATE (flagged 2026-08-05): the trading agent's droplet
  (see docs/DEPLOYMENT.md) runs Postgres directly on the same box rather
  than a DigitalOcean Managed Database, to keep it free while only the
  three agent-managed model portfolios (conservative/moderate/aggressive)
  exist and there's no real user data at stake. Once real users/production
  data are involved, move to a managed Postgres add-on (~$15/mo at time of
  writing) for automated backups, point-in-time recovery, easier
  scaling, and decoupling the database's lifecycle/uptime from the agent
  process's (right now a bad `systemctl restart britney-agent` or a
  droplet rebuild takes Postgres down with it).
- Deploy backend + Postgres somewhere real (see docs/TECH_STACK.md) — the
  agent now has this (docs/DEPLOYMENT.md), the FastAPI web app still doesn't.
- CI: pytest suite exists now (18 tests, all passing) but nothing runs it
  automatically — no CI/lint pipeline yet.
- Alembic migrations instead of relying on create_all (breaks on schema
  changes to existing DBs — currently working around this by deleting
  the local sqlite file).

MONETIZATION / PRODUCT (loose, unranked)
- Premium tier ideas: real-time data, more AI chat volume, tax-loss
  harvesting suggestions, deeper backtesting.
- Referral / waitlist mechanics for launch.
